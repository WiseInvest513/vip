# 市场观察：每周同步与归档

入口 `/daily` 默认读取最新发布的一期；固定链接为 `/daily?issue=weekly-YYYY-MM-DD`，日期使用**展望周的周一**。历期内容保留，新增一周不覆盖上一周。

## 每次同步

1. 在 `weekly/YYYY-MM-DD.ts` 新建一期，导出 `DailyIssue`，并在 `issues.ts` 导入、加入数组。数组自动过滤 `published` 并按 `dateISO` 倒序排列，不依赖手动插入顺序。不要把样稿放进发布清单。
2. 分别填入作者的原始发布日期 `dateISO`（北京时间）、显示日期 `date`、星期、`opinionTime` / `authorNote`；展望周期用 `periodStartISO`、`periodEndISO` 和 `periodLabel`。实际同步或部署日期不代替原始发布日期。没有可推断日期时先确认。
3. `id` 使用 `weekly-YYYY-MM-DD`；发布后保持稳定。完整正文按原段落写入 `sections`，保留标题、数字、观点和顺序。`lead`、`watch`、`stance` 仅作原稿摘要；不要把同步任务扩展成自行改稿或用最新数字覆盖历史观点。
4. 从该期原稿整理关注产品及观察周事件。`agenda.current` 指**该期覆盖的观察周**；`agenda.next` 仅收录原文明确提出的后续安排，没有则留空。时间使用北京时间，不凭空补充钟点或下一期日程。需要事实校订时独立核验并记录修订，不能声称原稿同步已做事实核查。
5. `npm run test:daily`、`npm run build`；预览 `/daily`、该期固定链接和上一期链接，检查默认最新、刷新、月份切换、整周点击、浏览器后退、日程重置、关注产品、手机窄屏与深色模式。确认旧正文未变、未加载其他期的全文。
6. 按仓库现有 Vercel 流程发布并检查线上 `/daily` 与固定链接。尊重仓库的推送权限及私人正文规则。

## 内容与页面职责

- `weekly/`：一周一个文件；`issues.ts`：服务端内容注册与排序。
- `app/daily/page.tsx`：解析 `issue`，无参数选最新、未知期返回 404；只向页面传递所选期全文和归档元数据。
- `components/daily/overview.tsx`：复用 `/join` 设计，显示原始发布日期与展望周期，提供按月翻页的周历与历史链接，每周一行，显示周次、周一至周五的起止日期和文章标题，不显示每日日期格。切换后日程回到观察周。
- 原有市场观察保持公开阅读。这里的 `server-only` 用来避免整套历史正文进入客户端静态包，不代表会员权限。

## 周历交互

- 目前市场观察每周一篇，以整周为阅读单位。每周一行，点击整行跳转对应固定链接并定位正文；没有周报的周只显示空状态。
- 周次从当月第一个周一算第 1 周；跨月观察周在两个涉及的月份均可找到，并保留其周一所属月份的周次。跨年同样处理。
- 支持上月、下月、归档月份选择与回到本期。只需新增周报元数据，周历自动生成，无需手工维护日期格或列表。
